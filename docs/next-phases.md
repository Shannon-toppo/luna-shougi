## フェーズ7: 足場を固める(1〜2日)

新しい実験に入る前に、崩れると全部が信用できなくなる箇所を先に閉じる。安いものばかりなので順番は問わない。

1. **PR #13 をマージする。**mainに世代1の量子化が無いと、`nets/*-g1.nnue` が読めるビルドとそうでないビルドが混在する
2. **`luna-match` に規律3を組み込む。**対局開始前に両側の `info string eval ...` を読み、期待した評価(nnue / hand-written)と一致しなければ対局を始めない。罠15(幅違いのファイルを黙って拒否)と罠18(既定で `eval.nnue` を読む)の両方がこれで塞がる。**幅が2つ、既定が NNUE になった今、これは任意ではない**
3. **山の位置を絞る。**1,562 / 3,125 / 6,250 を世代1ネットで1000局の直接対決(3組、約1時間)。定数ずれは -4.5 / +0.9 / +11.6 で、差は最大16点(≒29 Elo)。**6,250 対 1,562 の差がこの幅を越えなければ「1,500〜6,000 のどこでも同じ」で確定させ、3,125 を既定にする。**フェーズ8以降のレシピをここで固定するのが目的で、頂点の主張が目的ではない

5. **`dist/` のリリースを切る。**`eval.nnue` を exe の隣に置いた v0.7 パッケージは手元にあるが、gen10-s3125-g1 を `eval.nnue` として同梱したものを ShogiGUI と ShogiHome の両方で実際に1局指す。**フェーズ2以来、GUI 経由の確認は NNUE で一度もしていない**

## フェーズ8: 時計のある盤に戻る(3〜5日)

**これがこの計画で最大の未知である。**固定深さで積み上げた +100 Elo が、持ち時間では NPS 0.58倍とマージンの不整合で削られる。どれだけ残るかは測るまで分からない。

1. **基準点を1つ取る。**gen10-s3125-g1 対手書き、200ms/手、400局、8並列(`docs/measuring.md` の条件)。**固定深さの64%がここで何%になるかが、以降すべての判断の起点になる。**50%を割っていたら、フェーズ9より先にここを直す
2. **枝刈りマージンを NNUE のスケールで測り直す。**190/180/200 は手書き評価の単位(歩=90)で置いた値で、`docs/nnue-plan.md` の後回し欄に「持ち時間対局に切り替えるときに対照実験する」とある。1つ動かすたび400局、`docs/search.md` の手順。**NNUE の出力sdは 2,860 で手書きの 2,770 と近いので、大きく動く見込みは薄いが、ゼロと決め打ちはしない**
3. **NPS 0.58倍の内訳を測る。**`bench` で特徴変換器の差分更新・L1・出力層の時間を分け、罠なしで速くできる箇所(蓄積器のコピー、AVX2 の幅、`Clamp8` のシフト)を1つずつ。**幅の調査で「主犯は密な L1 の演算」と分かっているので、そこから**
4. **幅512の時間制対局。**`docs/nnue-quantization.md` 6節が「時間制の直接対決が要る」として残したもの。上の 3. で NPS が縮まっていれば条件が変わるので、その後に測る。+15 が残るか消えるかで `docs/nnue.md` の「1層目を広くするのが一番強くなる方向」を最終的に書き換える
5. **Lazy SMP と NNUE の相性。**8スレッドの +173 Elo は手書き評価で測った数字。NNUE は蓄積器をスレッドごとに持つので、メモリ帯域の取り合いが手書きより出やすい(幅の調査で8並列時 0.84倍を実測済み)。`--concurrency 1` で 8スレッド対 1スレッドを100局

完了条件: 時間制の対手書き勝率が記録されていること、マージン5本が各400局で測られていること。**判定は全部盤上、比較は直接対決**(規律1・5)は固定深さのときと変わらない。

## フェーズ9: 教師を NNUE に切り替える(1〜2週間、CPU 占有)

50% ゲートを越えたので `docs/nnue-plan.md` 第4項の条件が満たされ、`docs/nnue-step-budget.md` の「次にやること」2. がこれにあたる。**ただし gen1 の構図(弱いラベルの蒸留)に戻らないよう、順序を守る。**

1. **先に木を採り直す。**混合30%の探索木プールは gen7 の探索から採っている。gen10-s3125-g1 の探索で `treedump.py` を回し、同じ30%で組み直す。1回転 +29 Elo と測ってある実証済みのレバーで、24時間。**ラベルはまだ手書きのまま**
2. **ラベル付けを NNUE に切り替える(一変数)。**同じ局面集合を `--eval-file` で深さ6ラベル付けし、手書きラベルの対照と直接対決1000局。**局面と評価を同時に変えない**(深さ8の実験と同じ設計。詰みは和集合で落とす)。NNUE の NPS が 0.58倍なので、1421万局面のラベル付けは手書きの 20時間から 35時間前後に伸びる。**30分以上の作業はすべて開始前に確認する**
3. **自己対局の生成も NNUE に切り替える。**`luna-datagen` を `eval.nnue` 同梱のビルドで回し、`--score-limit 16000`、深さ6。2. で NNUE ラベルが勝っていることが前提
4. **step 予算を再測する。**データが変わればあの山が同じ位置にあるかは分からない(`docs/nnue-step-budget.md` の 3. が「別のデータ・別のレシピでも同じ形をするのか分からない」と書いているのはこのこと)。`--keep-every` を細かくした1本の長い学習から、checkpoint を降りて曲線を引く(罠16、学習コスト1本分)
5. **`--lambda-score` を下げる。**教師超えを狙う段階に来た(`docs/nnue-plan.md` 第4項の後段)。ratio0 の対照では +26.5、gen7 のレシピでは +0.7 と、レシピによって効き方が変わるので、NNUE 教師で改めて 1.0 / 0.7 / 0.5 を測る

完了条件: NNUE ラベルの世代が手書きラベルの対照に直接対決で勝ち、時間制の対手書きでフェーズ8の基準点を更新していること。**ここから先はループなので、1回転ごとに `docs/nnue-genNN.md` に記録する。**

## フェーズ10: step 曲線の機構を説明する(並行、GPU 空き時間)

**効果が先にあって診断が無い唯一の発見。**フェーズ9と並行して、学習は1分なので GPU が空いた時間で回せる。盤上の判定は各1000局。

疑うべき順に:

1. **学習率。**`--lr 1e-3`、`StepLR(2000, 0.99)`。100k step でも lr は 6e-4 までしか落ちず、最後まで大きな更新が続く。**「短いほうが強い」は「lr を落とし切る前に止めたほうが強い」と同じ現象かもしれない。**lr を 1e-4 に落とした 100k と、cosine で 0 まで落とした 100k を、s3125 と直接対決
2. **重みの平均(EMA)。**同じ 100k の学習で、step ごとの指数移動平均を別途書き出す。lr が原因なら EMA は s3125 に並ぶはずで、並ばなければ別の機構
3. **val の分布。**val 損失が盤上と符号ごと外れたのは、val が自己対局分布、盤は探索木分布だからかもしれない。**探索木6000局面上の残差(合格基準)を step ごとに引き**、それが盤上の山と同じ位置で折り返すなら物差しの問題として閉じる
4. **データ量との関係。**1421万局面で 3,125 step は 1.8 エポック。データを半分にして山が 1,562 に動くなら「エポック数」が、動かなければ「step 数(更新回数)」が本質
5. **seed。**seed 1、seed 2 で同じ曲線を引く。山が動かないことを確認しないと、上の全部が seed 0 の偶然かもしれない

完了条件: 「なぜ短い学習が強いか」に、**予測を先に書いて当てた**説明が1つ付くこと(`docs/nnue-quantization.md` 9〜10節の形式)。当たらなくても、潰した候補は記録する。
