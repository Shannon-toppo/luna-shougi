# 教師に探索木の局面を混ぜた — パイロットで-541 Elo、この事業で最大の効果

2026年8月17〜18日。`docs/nnue-plan.md` の2.をそのまま実行した記録。**教師データの局面そのものを、探索が実際に評価している局面に寄せた。**

391万…ではなく39万局面のパイロット、固定深さ6、各400局:

| | 結果 | Elo |
|---|---|---|
| 混合0% vs 混合10% | 34 - 362 - 4 (9.0%) | -401.9 ± 60.3 |
| 混合0% vs 混合30% | 17 - 383 - 0 (4.2%) | **-541.1 ± 91.1** |
| 混合10% vs 混合30% | 97 - 299 - 4 (24.8%) | -193.2 ± 39.5 |

単調で、**-541 Eloはこの事業が測った中で最大の効果**である。比較のため:損失の点数項は最大±155 Elo(`docs/nnue-gen4.md`)、ポナンザ定数は±133 Elo(`docs/nnue-search-distribution.md`)。

**まだフルスケールでは測っていない。**gen4の9.8%を超えたわけではない。この記録はパイロットと、その効果が何によるものかを一変数まで詰めたところまでである。

## 何がずれていたか

`docs/nnue-search-distribution.md` が測った本体は、ラベルの検閲のさらに下にあった。**教師は対局に現れた局面、消費者は静止探索のstand-pat。**gen3は `--score-limit` を上げてラベルの帯を直したが、局面そのものは手つかずだった。

実物を採って並べると、ずれは \|score\| の分布としてはっきり出る:

```
                                 n     0-300   300-600  600-1200 1200-3000 3000-5000 5000-16000   mean|x|
  教師 gen3-slice          391,831      30.4      9.8      14.7      24.7      11.6      8.8       1771
  探索木プール(詰み除く)  128,536      10.6      7.2      13.6      30.9      18.3     19.3       2840
```

**教師の40%は\|score\| 600未満で、探索木では18%。**逆に5000超は教師の8.8%に対し木では19.3%。平均の絶対値で1771対2840。同じ深さ6・同じ手書き評価で付けたラベルなので、これは検閲の差ではなく**局面の差**である。

## 作り方

**ダンプ。**`training/treedump.py` で gen4 の探索が `data/gen3-slice.sfen` の200局面から6手ずつ指す間の静的評価を採った。stride 64、32,626,244回の評価から509,786記録。

```
    standpat   421,490   82.7%
       prune    88,296   17.3%
```

`docs/nnue-search-distribution.md` が測った84〜88% / 12〜16%と同じ形。**駆動する評価はgen4** — 消費者はネットワーク自身の探索なので、gen2の木ではなくgen4の木を採った。

**ラベル。**150,000局面を抽出し、`luna-datagen --label --depth 6` で**手書き評価**が付けた。教師超えの前に `--eval-file` で生成しないという規律(`docs/nnue-plan.md` 4.)に従う。59局面/秒、42分。

**詰みを落とした。**21,464件、14.3%。`training/model.py` が「静的評価に+32000を回帰させても何も教えない」と書いているとおりで、Huber項は16000でクランプするから残せば出力をそこへ引く。3000超はそのまま残した —— そこが目的である。

**混合比は先に数字で決めた。**10%と30%、そして**総数を391,831に固定した**。木の局面は教師の局面を置き換えている。3本とも同じ局面数・同じstep数・同じseed・同じ `--score-weight 0.03` で、違うのはcompositionだけ。

```
  mix0    391,831 = 391,831 教師 +       0 木   |score|>=3000  20.4%
  mix10   391,831 = 352,648 教師 +  39,183 木                  22.2%
  mix30   391,831 = 274,282 教師 + 117,549 木                  25.6%
```

10%のプールは30%のプールの前半なので、**2本は「どの木を見たか」ではなく「どれだけ見たか」で違う**。

**ホールドアウトとの重複は0局面。**`data/tree-gen2.bin` はこの事業で唯一検閲されていないホールドアウトで、gen3以降の合格基準は全部そこで測っている。訓練プールと1局面でも共有していたら答えが訓練データに入る。混合スクリプトが機械で確かめて、重複があれば止まる。

## 道具の制約を1つ回避した(コードを変えた)

`luna-datagen --label` は **`result` を全サンプル0で書く**。仕様で、`src/datagen/datagen.cpp` に理由も書いてある —— 探索木から取った局面には周りに対局が無い。同じコメントが結論も書いている:

> fine to measure against and wrong to train on: train.py mixes the result into its target, and would read every one of these as a draw.

そのまま混ぜると `--lambda-score 0.7` の下で木の局面の目標が 0.3 × 0.5 だけ引き分け側に寄る。**勝勢の局面を「勝率0.85」と教えることになり、しかもそれは尾部で最大に効く。**

3つの道があった。(a) 両armを `--lambda-score 1.0` にする —— 結果項を全員から外すので変数が2つ増える。(b) 木のサンプルだけ結果項を外す。(c) そのまま混ぜる —— 上のとおり誤り。

**(b)を選んだ。**`result` は int8 で -1/0/+1 しか使っていないので、4つ目の値を足した。

- `training/dataset.py` に `RESULT_UNKNOWN = 2`
- `training/model.py` の `loss()` が、その印の付いたサンプルだけ実効lambda 1で学習する

**エンジンは触っていない。**印を打つのは混合スクリプトで、`luna-datagen` の出力はそのままである。

印の無いファイルに対しては**ビット単位で従来と同じ**であることを確かめた:

```
  no sentinel   old 0.230499401689  new 0.230499401689   equal True
  all sentinel  lambda 0.0 / 0.7 / 1.0 すべて 0.286468207836 = 点数のみの損失
  mixed halves add up  True
```

だからcontrolの `nets/sw003.nnue`(`docs/nnue-gen4.md` の重みグリッドで学習済み、同じデータ・同じ引数・同じseed)を再学習せずそのまま使える。

## 効いたのは局面のほうだった —— 一変数の対照

**mix30はmix0と2つ違う。**局面の30%が探索木のもので、しかもその30%は結果項を持たない。-541 Eloという大きさの主張を「分布が効いた」と書くには、この2つを分けなければならない。

`data/mix30-noresult.bin` を作った。**controlの局面をそのまま**、ランダムな30%だけ `RESULT_UNKNOWN` を打ったもの。同じ局面数・同じレシピ・同じseed。**mix30のlambda構造と、mix0の局面**を持つ。

| | 結果 | Elo |
|---|---|---|
| mix0 vs noresult | 203 - 192 - 5 (51.4%) | **+9.6 ± 34.0** |
| noresult vs mix30 | 21 - 376 - 3 (5.6%) | -489.9 ± 76.5 |

**結果項を30%外すことは、盤上で何もしない**(51.4%、区間が0をまたぐ)。そして noresult は mix30 に mix0 とほぼ同じだけ負ける(5.6%対4.2%)。

探索木の残差も同じことを言う:

```
                  max |x|      sd  resid no mates  tail out  resid deciding
  mix0                8112    2109            1841      2438            1087
  noresult            8318    2111            1873      2453            1123
  mix10               8442    2071            1730      2494             950
  mix30               9233    2080            1644      2385             784
  hand-written       10228    2769             818      3837             653
  gen4 (フル)         9067    2574            1202      3462             745
```

**noresult は全列で mix0 の複製**(1873対1841、1123対1087)。**効いたのは局面である。**

## 形が今までと違う

点数項(`docs/nnue-gen4.md`)は**尾部を買って決着帯を払う**取引だった —— 範囲が2634から9067へ伸び、決着帯は598から745へ悪化した。ポナンザ定数も同じ形で、そちらは払いすぎて盤上で負けた。

混合はそうではない。

- `tail out` は 2438 → 2385 で**動いていない**。範囲は買っていない
- `resid no mates` は 1841 → 1644
- **`resid deciding` は 1087 → 784**。手書き評価の653に、この事業で初めて近づいた

**両方の帯で精度が上がっている。**綱引きになっていない。範囲は点数項が既に買ってあるので、混合が売っているのは別の商品 —— **その範囲での当て方**である。

指標の側から見ると、決着帯の残差が初めて盤上と同じ向きに大きく動いた。この指標は `docs/nnue.md` が合格判定に使ってgen2を394敗させ、`docs/nnue-gen4.md` ではgen4を却下しかけた。**今回は当てている。**ただし4回外して1回当たった指標であって、これで信用が戻るわけではない。

## まだ言えないこと

**フルスケールでどうなるかは分からない。**`docs/nnue-gen4.md` の追記が測ったとおり、**スライスのパイロットは順位を当てて勝ち幅を当てない** —— 点数項はスライスで+103 Elo付けて、1421万局面では+32 Eloに縮んで消えた。39万局面で混合が買っているものの一部を、1421万局面はデータ量だけで買っている可能性がある。

**30%はまたグリッドの端である。**50%や100%がどうかは測っていない。そして端の勝者を信じて上に伸ばした前回(w=0.3)は、フルスケールで何も出なかった。

**混合ラベルは付け方が2種類ある。**教師の行は自己対局(置換表を1局持ち越す)、木の行は付け直し(1局面ずつ表を空にする)。`docs/nnue-search-distribution.md` の罠8のとおり、この2つは同じ深さでも一致しない。混合ファイルはその2つが混ざっている。避けられないので書いておく。

名前を分けた。この記録のダンプは、直したあとで抽出だけ回し直して作ってある(`subsample` は決定的なので同じ `.sfen` になる)。

`luna-datagen --label` の話。**ドキュメントには書いてあった** —— `--help` にも `src/datagen/datagen.cpp` のコメントにも、「measure against するのは正しく、train on するのは誤り」と。`docs/nnue-plan.md` の2.はそれを読まずに「`--label` でラベルを付けて `data/gen3.bin` に混ぜる」と書いていた。

### 対手書き評価では、片方しか動いていないように見えた

| | 結果 | Elo | 勝率の95%区間 |

**先に宣言した合格ライン(gen4の区間の外 = 12.7%超)は mix30 が越えた。**そして mix10 は gen4 と同じところに落ちた。

**その合格ラインは検定として不正である。**新しい点推定を古い区間と比べるのは、新しい側の不確かさを数えない形になっている。両方の誤差を入れると:

| | 結果(1000局) | Elo |
|---|---|---|

### 壊れていたのは「手書き評価を経由した比較」

同じ差を2通りに測ると:

| 比べたもの | 手書き経由 | 直接対決(1000局) | 比 |
|---|---|---|---|
| gen2 → gen3 | +59 | **-4.2 ± 21.5**、LOS 35% | どちらも「無い」 |
| gen3 → gen4 | +313 | +304.1 ± 30.4 | **1.0** |
| gen4 → gen5 | +32 | +164.5 ± 23.9 | 5.2 |
| gen4 → gen6-mix10 | **-5** | +120.7 ± 22.7 | 符号が逆 |
| gen4 → gen6-mix30 | +54 | +196.0 ± 24.9 | 3.6 |

**境目はgen4にある。**gen4以下の2つは両方の測り方が一致し、gen4以降の3つは3〜5倍に潰れるか、まったく見えない。gen4→mix10 は121 Eloの改善が「-0.25ポイント、p=0.90」として出た。

gen2→gen3 は**両方とも「差は無い」と言っている**ことに注意。しかも直接対決の区間は ±21.5 Elo で、`docs/nnue-search-distribution.md` が400局で出した結論(「上限を上げたことは勝率を動かしていない」)は正しく、いま桁違いの精度で確認された。**手書き経由が常に嘘をつくのではない。**

何がgen4で切り替わるのかは、この記録では分かっていない。gen4は出力レンジを取り戻した最初の世代なので、そこで対局の質そのものが変わった可能性はあるが、**測っていないので仮説である。**分かっているのは**gen4以降の帯域で、対手書き勝率が世代間の差を測る道具になっていない**という事実のほうである。

**実務上の結論は明確である。**

> **変更が効いたかどうかは、直前の世代との直接対決で測る。対手書き勝率は目標の指標であって、比較の道具ではない。**

400局で±3ポイントのノイズがあり、そこに3〜5倍の圧縮がかかる。この2つが重なると、100 Elo級の改善が誤差として消える。実際に消した。
