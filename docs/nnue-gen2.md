# 第2世代NNUEの記録 — 指標を3回作り直して、3回とも外した

2026年8月11〜12日。`docs/nnue-gen1.md` の「次にやること」をそのまま実行した記録。深さ6で1124万局面を作り、学習し、測った。

結果は**失敗**で、gen2は手書き評価に固定深さ6で 4-394-2(1.3%)。固定深さ2でも 5-395-0(1.3%)。

gen1の記録は「深さ4が悪かった」という原因の記録だった。こちらは違う。**原因は分かっていない。**この記録の内容は、原因を探す過程で私が同じ間違いを3回繰り返したことと、その間違いの形である。

## 結論から

**盤上の結果と結びつくことを確かめていない指標で、判断してはいけない。**

この2日で3つの指標を作った。どれも測れて、どれも数字が動いて、どれも対局結果と無関係だった。3つ目に至っては「合格」と判定したネットが400局中394敗した。

指標を作ったら、**既知の対局結果を再現できるかを先に確かめること**。gen1(1-399-0)とgen2(4-394-2)という2つの実測がある以上、新しい指標はまずこの2つを説明できなければならない。

## 何を回したか

| | |
|---|---|
| データ生成 | `--games 90000 --depth 6 --openings 8 --concurrency 16`、約25時間、**1124万局面**(944MB) |
| 学習 | `--steps 100000`、バッチ8192、**72エポック**、RTX 4070 Ti で約30分、55 steps/s |
| ホールドアウト | `--games 60 --depth 6 --seed 999`、7489局面 |
| 訓練loss | 0.0100 → 0.0025 |
| 強さ(固定深さ6) | **4 - 394 - 2**、400局、1.3%、Elo -759.1 ± 73.7 |
| 強さ(固定深さ2) | **5 - 395 - 0**、400局、1.3%、Elo -759.1 ± 75.9 |

深さ2と深さ6で結果が同じだったことは、それ自体が情報になっている。アキュムレータの差分更新は探索が深いほど連鎖が長くなるので、そこにバグがあるなら深さで結果が変わるはずだった。変わらない。

## 指標を3回作り直した

### 1回目: 訓練lossだけを見ていた(gen1)

`docs/nnue-gen1.md` に書いたとおり。訓練lossが1000分の1に落ちたのを成功と読んだ。対策として `--val-data` を入れた。

### 2回目: 残差sd(全体)

未知局面でのラベル予測誤差。手書き評価が455、gen2が622で「失敗」と判定した。

ところがラベルの大きさで分けると絵が変わる。

```
  |label| band      n  hand-written          gen1          gen2
         0-300    970           327           382           305
       300-600    271           504           601           357
      600-1200    417           572           837           473
         1200+    842           565          1525           935

       overall   2500           484           999           618
```

**gen2は1200未満の全域で手書き評価より正確**で、負けているのは1200以上だけ。そこが34%を占めるので全体が逆転していた。

これは損失関数の設計そのものだった。学習しているのは `sigmoid(score/600)` の勝率で、「+1500と+3000は指し手として同じ」というのがポナンザ定数の意味である。**その「区別しなくていい」と宣言した領域を、3分の1の重みで採点していた。**

### 3回目: 残差sd(決着帯 |label| < 600)

帯域を絞った。float モデルで測ったもの:

| | 決着帯 | 全体 |
|---|---|---|
| 手書き評価 | **376** | 484 |
| gen1(399/400で負けた) | 436 | 998 |
| gen2 | **310** | 622 |

この指標はgen1を正しく「失敗」と判定する(436 > 376)。gen2は手書きを16%上回って「合格」。**そのgen2が400局中394敗した。**

指標を直したこと自体は正しい(2回目の指標はgen1もgen2も同じく失敗と言い、区別できなかった)。間違っていたのは、**既知の対局結果1つ(gen1)を説明できただけで、予測できると信じたこと**。1点を通る指標は無数にある。

## 分布外での崩壊

対局結果がネットワークの質に反応しないことに気づいて(gen1→gen2で決着帯436→310、データ4.8倍、勝率0.3%→1.3%)、探索木の中身は訓練分布の外だろうと考えた。

開始局面のランダム手数を8から40に増やしたデータ(`--openings 40 --seed 777`)で同じ測定をした。

| | 訓練分布 (holdout6) | 分布外 (wild) |
|---|---|---|
| 手書き評価 | 455 / +0.933 | **543** / +0.936 |
| gen2 | 629 / +0.868 | **1067** / +0.732 |

手書き評価は分布が変わってもほとんど劣化しない(材料とPSTの滑らかな関数なので当然)。gen2は70%劣化する。

**これは本当の現象で、いまも成り立っている。**ただし原因ではなかった。

### 対照実験: 開始局面のランダム化では直らない

局面数・深さ・ハイパラを完全に揃え、**訓練データの分布だけ**を変えた2本。

| | holdout6 | wild |
|---|---|---|
| A: 39万局面、開始8手 | 609 / +0.877 | **1301** / +0.567 |
| B: 39万局面、開始**30**手 | 1019 / +0.617 | **1271** / +0.605 |

分布外で 1301 → 1271、**2.3%**。相関は +0.567 → +0.605。この幅では説明にならない。

比較のため、同じ狭い分布でデータ量だけ28倍にしたgen2は分布外1067。**開始局面のランダム化より、単純なデータ量のほうが効いている。**それでも手書き評価の543には遠い。

この対照実験の価値は、**19時間を投じる前に否定できたこと**にある。`--openings 30` での本生成はしない。

## 測定の罠(gen1の続き)

### 6. `go` の直後に `quit` を送ると探索が中断される

```bash
printf "usi\nisready\nposition startpos\ngo depth 6\nquit\n" | luna-shougi.exe
```

`bestmove` は返ってくる。`info` 行は1つも出ない。エンジンは正しく動いていて、**探索中に届いた `quit` で打ち切っている**(`tests` の「quit during a search ends it and still answers the go」がその仕様)。

パイプに全部流し込む書き方は `eval` のような同期コマンドでは正しいが、`go` では測定にならない。`bestmove` を読んでから次を送ること。

### 7. 混ぜる比率を計算していなかった

パイロットの最初の設計は「開始30手のデータを60局作ってgen2のデータに混ぜる」だった。60局は約5000局面、gen2は1124万局面。**混合比 0.04%** で、分布を変える実験になっていない。

データセットを混ぜる実験を設計したら、比率を数字で出すこと。

## 未解決の観察

原因の候補として調べたが、結論を出せなかったもの。

**構成した局面での材料の値付けが手書き評価と大きく違う。**平手初期局面(先手番、先手視点)からの差分:

| | 手書き | gen2 |
|---|---|---|
| 先手の飛車を除く | -996 | -499 |
| 後手の飛車を除く | +996 | +1129 |
| 先手の飛車を持ち駒に | +34 | +305 |

ただし**この比較は先後対称性の検査にはなっていない**。「先手の飛車を除いた先手番の局面」の先後反転は「後手の飛車を除いた**後手番**の局面」であって、上の表の2行目ではない。特徴量の先後反転は `tests/test_nnue.cpp` が検査していて通っている。数字が手書き評価と離れていること自体は事実だが、バグの証拠にはなっていない。またこれらは自己対局に現れない構成局面である。

**PVが手待ちになる。**平手初期局面でgen2は `6i6h` を選び、PVの4手後に `6h6i` と戻す。手書き評価は `7g7f` から普通に組む。候補手の優劣を分解できていない挙動に見えるが、1手違いの局面ペアでの変化量の残差を測ると gen2 213、手書き 572 で、gen2のほうが良い。説明がついていない。

## この記録のネットワークは量子化補正の前のもの

**`nets/gen2.nnue` は `quantize.correct_biases` が入る前に書き出したファイル**である。上の対局も測定も全部それで取った。

補正は同じネットワークどうしの比較で **+62.3 ± 34.5 Elo**(別シードで +40.1 ± 34.3)の価値があると測られている(`docs/nnue-gen1.md`)。gen2が負けた幅は -759 Elo なので、**補正の不在はこの失敗を説明しない**。桁が2つ違う。

それでも、次に何かを試す前にこれを済ませるべきである。再エクスポートは1分、対局のやり直しは30分で、以降の測定が全部この土台に乗る。

```bash
uv run python -m training.serialize runs/gen2/checkpoint.pt nets/gen2.nnue --calibration data/gen2.bin
uv run python -m training.drift --checkpoint runs/gen2/checkpoint.pt --net nets/gen2.nnue --sfen data/holdout6.sfen
```

`drift.py` はこの記録を書いている時点でgen2に対して回していない。**gen2の定数ずれが何点だったかは分かっていない。**±30点程度の分布から引くものなので、gen1の-34.6とは無関係な値になる。

## 次にやること

**推測でデータセットを作るのをやめる。**

この2日で作った代替データセット(holdout6、wild)は、どちらも「探索木の中身はこういうものだろう」という推測から作った。3回とも盤上の結果と結びつかなかった。

探索中に評価した局面を `(sfen, 使った評価値)` で書き出すデバッグ経路をエンジンに足せば、静止探索の途中や取り合いの最中を含む**実物の分布**が採れる。それを深い探索でラベル付けし直せば、どの局面でネットワークが壊れているかが推測なしで分かる。

新しい指標を作ったら、その指標が gen1(1-399-0)と gen2(4-394-2)の両方を説明できることを先に確認すること。できないなら、その指標では判断しない。

## 使ったもの

- `training/baseline.py` — ホールドアウトでの残差sd。`--net` で学習済みネットも同じ物差しで測れる
- `training/holdout.py` / `train.py --val-data` — 学習中の検証。分布の狭いホールドアウトだけを見ても、この失敗は見えない
- `training/drift.py` — floatモデルと量子化ネットワークの平均のずれ。**この記録の測定には使っていない**(補正と同時に入ったため)。次の世代では書き出しのたびに通すこと
- `data/holdout6.bin`(深さ6、開始8手、seed 999)、`data/wild.bin`(深さ6、開始40手、seed 777)
