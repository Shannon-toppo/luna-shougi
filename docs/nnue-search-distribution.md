# 探索木の分布を実測した — 原因は `--score-limit`

2026年8月12日。`docs/nnue-gen2.md` の「次にやること」をそのまま実行した記録。**推測でホールドアウトを作るのをやめ**、探索が実際に評価した局面を書き出して測った。

結果は**原因の特定**である。gen1もgen2も、負けた理由は同じ1行だった。

```
--score-limit 3000   # luna-datagen の既定値
```

## 結論から

**教師データを作るときに捨てた局面が、探索が評価する局面の37%を占めていた。**

| | 教師データ(gen2.bin) | 探索木(gen2が歩く実物) |
|---|---|---|
| \|score\| ≥ 3000 | **0.00%** | **37.5%** |
| \|score\| ≥ 5000 | 0.00% | 18.9% |
| 詰みスコア | 0.00% | 9.4% |
| 最大の\|score\| | **2998** | 31999 |

`--score-limit 3000` は決着済みの局面を教師から除く。狙いは正しく、`docs/nnue.md:106` に「出力レンジを引っ張るだけになる」と書いてある。**そのとおりになった。引っ張られなかったので、出力レンジがそこで止まった。**

ネットワークが出せる点数の上限を5000局面で測ると:

| | 出力の\|x\|中央値 | 出力の\|x\|最大 | 出力のsd |
|---|---|---|---|
| 手書き評価 | — | **10058** | 2770 |
| gen1 | — | **3186** | 763 |
| gen2 | — | **2634** | 898 |
| ラベル(深さ6) | — | 31999 | 9924 |

**gen2は2634点より上を出せない。**教師の最大が2998なので当然で、これは学習の結果である。**量子化のせいではない** — floatモデルで測っても最大2636、量子化ネットとの差は最大111点しかない。

そして探索木の37.5%はその外側にある。

**詰み帯だけは全員が同じように駄目**(1.06)。静的評価に±32000を期待するほうが間違いなので、これは正常。

## この指標は既知の対局結果を説明するか

`docs/nnue-gen2.md` の規律。**新しい指標は gen1(1-399-0)と gen2(4-394-2)の両方を説明できなければ使ってはいけない。**

2つの対局は Elo -800 と -759 で、**ほぼ同じ**。つまり指標は「手書き ≪ gen1 ≒ gen2」と言わなければならない。同じ測定を6通りに読んで、全部を機械的に判定した:

```

  reading                   hand-written    gen1    gen2   verdict
  resid sd, all                     8729    9691    9522   consistent
  resid sd, no mates                 817    2593    2423   consistent
  resid sd, |label|<3000             728    1407    1264   consistent
  resid sd, |label|<600              662     644     605   FAILS: ネットを手書きより上に置く
  win-rate rmse x1000                200     329     278   consistent
  corr with label                  0.545   0.339   0.483   FAILS: gen1とgen2を離しすぎる
```

**合格するのは「詰みを除いた残差sd」**で、817 対 2593 対 2423。手書きの3倍、そしてgen1とgen2は7%しか違わない。盤上と同じ形である。

`docs/nnue-gen2.md` が予想した「手書きが543のところ、gen2が2000ある」という形が、実際に 817 対 2423 で出た。

### 今までの合格基準は、探索木の上でも間違っている

`|label| < 600` の残差sd —— `docs/nnue.md` が合格判定に使い、gen2を「合格」と判定して394敗させた指標 —— は、**4つのデータセット全部で判定に失敗する**。

| | 手書き | gen1 | gen2 | |
|---|---|---|---|---|
| holdout6 | 357 | 437 | **320** | gen2が手書きより上 |
| wild | 480 | 583 | 541 | 一応通る |
| 探索木(手書き) | 556 | 559 | **555** | gen2が手書きより上 |
| 探索木(gen2) | 662 | 644 | **605** | gen1もgen2も手書きより上 |

**gen2が歩いた探索木の上でさえ、この指標はgen2を手書き評価より上だと言う。**決着帯だけを見ているかぎり、どこで測っても答えは変わらない。`docs/nnue.md` の「足切りであって合格証ではない」は、想定より強く成り立っていた。

## 「探索木だから」なのか「ラベルが大きいから」なのか

分けて確かめた。帯域を揃えて比べると、**600以上のどの帯域でも、どのデータセットでも、ネットワークは手書きより悪い**。探索木に固有の局面があるわけではない。

違うのは**重み**である。

```
share of each |label| band     holdout6     wild   tree hand   tree gen2
        3000-5000                  0.5%     0.7%       11.0%       18.7%
       5000-10000                  0.0%     0.0%        0.7%        9.3%
       31000+ (mate)               0.0%     0.1%        9.0%        9.4%
```

holdout6は3000以上を0.6%しか持たない。**持てない** —— 同じ `--score-limit 3000` で作られているからである。

ここが方法論として一番効く点で、

**ホールドアウトは教師データと同じ検閲を受け継いでいた。**holdout6もwildもwideも、全部 `luna-datagen` の既定値で作った。だから3000以上が存在しない。**存在しない帯域は、どう切り直しても見えない。**前のセッションが3つの指標を作って3つとも外したのは、指標の切り方が悪かったからではなく、測っていたデータに答えが入っていなかったからだった。

## 因果の鎖

1. `--score-limit 3000` が決着済みの局面を教師から全部落とす。gen2.bin の最大ラベルは **2998**
2. ネットワークは±2600ちょうどで頭打ちになる。**floatモデルでも同じ**(最大2636)なので、量子化でも書き出しでもなく学習の結果
3. 探索は評価の **37.5%** をその外側で使う。19%は5000超、9.4%は詰み
4. その帯域でネットワークの残差は手書きの **3.3〜4.7倍**
5. gen1とgen2は同じ欠陥を共有する(同じ既定値、同じ上限)。**だから4.8倍のデータも決着帯の残差436→310も、勝率を0.3%から1.3%にしか動かさなかった**

損失関数もこれを後押ししている。学習する目標は `sigmoid(score/600)` で、2600点は sigmoid で 0.988。そこから先は勾配がほぼ0なので、**仮に教師に5000点の局面があっても学びにくい**。ただし今回に限れば、その議論をする前に教師に1局面も入っていない。

### `--score-limit 16000` で作り直した

非詰みラベルの実測最大が10822、生成し直したデータでの最大は15232だったので、16000は非詰みを一つも落とさない。詰みは `IsMateScore` が別に弾く。

### 2×2で測った

39万局面(`gen2-slice.bin` と同サイズ)、30000step、seed 0、lr 0.001、lambda 0.7。探索木6000局面での測定。

```
                      max |x|     sd  resid no mates  out @|label|>=3000  resid deciding
  limit  3000, C= 600    3001    718            2592                 683             605
  limit 16000, C= 600    3713    984            2439                 937             708
  limit  3000, C=1800    3681   1150            2504                1118            1037
  limit 16000, C=1200    5462   1435            2223                1514             997
  limit 16000, C=1800    7028   1757            2128                1829            1242

  hand-written          10228   2769             818                3837             653
  label                 31999   9897               0                5009               0
```

**上限だけでは足りない。**3000超での出力は683から937にしか動かない。損失が `sigmoid(score/600)` である以上、3000点と8000点の目標は 0.9933 と 0.9999985 で、データを見せても差を出せという勾配が立たない。

**2つの要因は掛け算になる。**両方入れると683が1829まで伸びる。範囲そのものは確かに買い戻せる。

**そして決着帯は単調に壊れる。**605 → 708 → 997 → 1242。手書き評価は653なので、**元のgen2の作り方が決着帯では手書きより優秀で、C=1800はその半分**になる。

### 盤上は残差と逆を言った

同じデータ・同じstep、定数だけ違う3本の総当たり。固定深さ6、各400局。

| | 結果 | Elo |
|---|---|---|
| C600 vs C1200 | 262 - 136 - 2 | **+113.3** ± 35.9、LOS 100% |
| C1200 vs C1800 | 252 - 141 - 7 | **+99.0** ± 35.3、LOS 100% |
| C600 vs C1800 | 273 - 127 - 0 | **+132.9** ± 36.8、LOS 100% |

**C600 > C1200 > C1800。**3組とも LOS 100%、誤差幅の3倍。単調で、推移律も向きが揃っている。

**ポナンザ定数を上げるのは誤りだった。**残差では「尾部を1.6倍取り戻して決着帯を1.4倍失う」取引に見え、比では1200が有利にすら見えた。盤上は3組とも逆を言った。**決着帯の分解能のほうが、尾部の範囲より重い。**

定数は600に戻した。`training/model.py` にこの表を書いてある。

**これで残差の読み方と盤上が食い違ったのは5回目**である。違うのは、今回は判定を対局に委ねたので、19時間ではなく13分の学習で分かったこと。**定数をいじるなら対局とセットでしか判断してはいけない。**

### 上限のほうはまだ否定されていない

否定されたのは定数だけである。`--score-limit 16000` は定数と直交する軸で、C=600 のまま上限だけを上げた行(937 対 683)は正しい向きに動いている。ただし**その差が盤上で何Eloになるかは測っていない** — 上の総当たりは3本とも上限16000で、上限そのものの対局比較はしていない。

gen3の本生成はこの追記の時点で進行中(90000局、約26時間)。**完成したら最初にやるべきは、上限3000と16000を同じ定数・同じ局面数で戦わせること。**

## 足した道具

| | |
|---|---|
| `EvalDump` / `EvalDumpEvery` USIオプション | 探索が取った静的評価を全部書き出す。既定で無効、無効時のコストは bool のrelaxed load 1回。ベンチのノード数は1つも変わらない |
| `luna-datagen --label FILE` | SFENを1行ずつ読んで深い探索でラベルを付け直す。入力の順序を保つので `.bin` と `.sfen` が行単位で対応し、`training/baseline.py` がそのまま読める |
| `training/treedump.py` | 実局面から指させながらダンプを採り、部分標本と `.sites`(どの評価だったか)を書き出す |

ダンプの列は `site / score / ply / worker / sfen`。`site` は `standpat`(静止探索、木の84〜88%)、`prune`(枝刈り用の静的評価、12〜16%)、`horizon`(ply上限、実測0件)。

`Threads` が1より大きいときは、記録は完全だが再現しない(ヘルパースレッドが各自の深さを各自の順で探索するため)。その旨をオプションが `info string` で言う。

## 測定の罠(gen1・gen2の続き)

### 8. ラベルの付け直しは自己対局のラベルと一致しない

`luna-datagen --label` で holdout6 の先頭300局面を付け直すと、元のラベルと **117/300 しか一致しない**。中央値の差は3点、p99で424点、そして2局面は詰みを見つけて30000点ずれる。

バグではない。自己対局は1局のあいだ置換表を持ち越すので、N手目の探索はN-1手目までの表を使える。付け直しは1局面ずつ表を空にして探索する。**深さが同じでも同じ探索ではない。**

だから**比較する数字は全部同じ付け方で作ること**。この記録の表はすべて `luna-datagen --label --depth 6` で付け直したラベルで測っていて、`data/holdout6.bin` に入っている元のラベルとは混ぜていない。

### 9. 検閲されたホールドアウトは検閲を報告しない

上に書いたとおり。holdout6 で3000以上の残差を測ろうとすると n=26 で「1092」という数字が返ってくる。**もっともらしく、しかも0.5%の標本**。帯域ごとの n を必ず出すこと。

- `training/treedump.py` — 探索木の採取と部分標本
