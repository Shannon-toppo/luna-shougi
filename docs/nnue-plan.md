## 順番

安いものから。判定は全部盤上で。

### 0. gen4を記録する — 済み

`docs/nnue-gen4.md`。唯一針を動かした実験の記録が `data/overnight.log` 1本しかなかった。overnightスクリプトは設計としてdocsに書かないことにしていた(数字が成果物)ので意図した状態ではあるが、失敗3回をここまで使える形にしたのは記録の質で、成功だけ記録しない理由はない。

書くにあたって2つ足りていなかったので測った。**合格基準(詰みを除いた探索木上の残差sd)がovernightのログに無く**、全世代を同じ6000局面で測り直した(手書き818 / gen2 2418 / gen3 2222 / gen4 **1202**)。`drift` の平均も `tail 6` に切られていたので取り直した(+3.6)。

### 1. score-weight を上に伸ばす — 済み。伸ばしても何も無かった

w ∈ {0.03, 0.1, 0.3} をスライスで総当たりし、勝者(0.3)を1421万局面で学習してgen5にした。記録は `docs/nnue-gen4.md` の追記。

**gen5 は 45-353-2(11.5%)。**先に宣言した合格ライン12.7%の内側で、gen4の9.8%との差は z = 0.80。**差は出ていない。**

スライスでは w0.3 が w0.03 に +103 Elo(LOS 100%)付けていた。フルスケールでは +32 Elo で消えた。**39万局面で重みが買っているものの一部を、1421万局面はデータ量だけで買っている** —— `--score-limit` のパイロットと同じ形である。

3つ持ち帰るものがある。

1. ~~**点数項は0.03で効いて、そこから先は平ら。**~~ → **8月19日撤回。**直接対決1000局で **gen5がgen4に +164.5 ± 23.9 Elo、LOS 100%**。この項は0.3でも効いている。撤回の理由は下の2.にある測定法の話で、対手書き勝率が世代間の差を潰していた
2. **スライスの総当たりは順位を当てるが、勝ち幅は当てない。**候補を落とすふるいとして使い、差の大きさはフルスケールで測り直すまで信じない
3. **`drift` は探索木で回す。**平均のずれは局面集合ごとに10点動き、閾値は8点だった。gen5は最初holdout6で落ちて、探索木では通った(-3.7)。規律4がdriftにも及ぶという話で、`training/drift.py` の既定値と `docs/nnue.md` の手順はまだ直していない

### 2. 教師の分布を探索木に寄せる — パイロットは済み。**この事業で最大の効果**

記録は `docs/nnue-tree-mix.md`。39万局面のパイロット、混合0% / 10% / 30%、各400局:

```
  混合0% vs 混合10%    34-362-4  ( 9.0%)   -401.9 Elo
  混合0% vs 混合30%    17-383-0  ( 4.2%)   -541.1 Elo
  混合10% vs 混合30%   97-299-4  (24.8%)   -193.2 Elo
```

比較のため、点数項は最大±155 Elo、ポナンザ定数は±133 Elo。**桁が違う。**

探索木では合格基準が1841→1644、**決着帯が1087→784**(手書き653)。点数項が「尾部を買って決着帯を払う」取引だったのに対し、**混合は両方の帯で精度を上げていて、範囲(tail out 2438→2385)は動かしていない。**綱引きになっていない。

一変数の対照も取った。controlの局面のまま30%に `RESULT_UNKNOWN` を打った `mix30-noresult` は、mix0に **203-192-5(+9.6 ± 34.0)** で並ぶ。**効いたのは局面であって、結果項を外したことではない。**

道具の制約を1つ回避してある。`luna-datagen --label` は `result` を0で書き、それは学習に使うと「全部引き分け」になる(罠13)。`dataset.RESULT_UNKNOWN` と `model.loss()` で、対局の無いサンプルだけ結果項を外した。**エンジンは触っていない。**

**残っているのはフルスケール。**同じ比率を1421万局面で作るには、木の局面が10%で142万(ラベル付け6.7時間)、30%で426万(20時間)。プールは使い回せるので426万を1度作れば両方組める。学習は32分。

判断の材料は2つ。**30%はまたグリッドの端**であること、そして**スライスのパイロットは順位を当てて勝ち幅を当てない**こと(点数項はスライスで+103 Elo付けてフルスケールで消えた)。

**フルスケールも通った(8月19日)。**560万局面をラベル付けし、詰みを落として459万。gen4と同じレシピで2本学習した。

| | 対手書き400局 | gen4との直接対決1000局 |
|---|---|---|
| gen6-mix10 | 9.50% | **+120.7 ± 22.7**、LOS 100% |
| gen6-mix30 | **12.88%** | **+196.0 ± 24.9**、LOS 100% |

**そして物差しが壊れていることが分かった。**対手書き勝率では mix10 は gen4 と区別がつかず(9.50%対9.75%、p=0.90)、mix30 も決着しない(p=0.16)。直接対決では両方 LOS 100%。同じ差を2通りに測ると、gen3→gen4 は一致するのに、gen4以降は3〜5倍潰れるか符号が逆になる。

探索木では gen6-mix30 が手書き評価にほぼ並んだ(合格基準988対818、尾部3902対3837、決着帯685対653)。**それでも87%負けている。この基準は天井に来た。**

詳細は `docs/nnue-tree-mix.md` の8月19日の追記。ゲートの通し方(定数を木の行で合わせた)と、見積もりを2つ外した話もそこにある。

### 3. 深さ8はスライスの付け直しで試す — 済み。**効くが、値段が合わない**

`data/gen3-slice.sfen` を深さ6と深さ8で付け直し、38.9万局面の2本を同じレシピ(30000step、`--score-weight 0.3`、seed 0)で学習した。

一変数にするための設計が3つ。**対照は「既存のラベル」ではなく「同じ局面の深さ6付け直し」**である(自己対局は置換表を1局持ち越すので、同じ深さでも付け直しと一致しない。罠8)。**詰みは和集合で落とした** —— 深さ8のほうが多く見つけるので各自で落とすと2本が別の局面を持つことになる(3,142局面、0.8%)。**対局結果は `gen3-slice.bin` から行対応で戻した**(罠13)。

| | 結果(1000局) | Elo |
|---|---|---|
| depth6 vs depth8 | 459 - 530 - 11 (46.5%) | **+24.7 ± 21.5**、LOS 98.8% |

```
                  max |x|      sd  resid no mates  tail out  resid deciding
  depth 6 labels    8296    2015            1855      2375            1108
  depth 8 labels    8971    2184            1776      2603            1113
```

**深さ8は本物だが小さい。**区間は [+3, +46]。gen1の「深さ6以上」は「6で十分」ではなかったが、**6が致命的でもなかった。**

**それでもフル生成77時間は払わない。**理由は3つ。

1. **+25はパイロットの数字で、パイロットは幅を当てない。**混合は 541(パイロット)→ 25(4.6M)→ 145〜196(14.2M)と動いた。上にも下にも外れる
2. **77時間は、フルスケールで測った最大のレバー(混合 +196、点数項 +165)と釣り合わない。**+25の候補に払う額ではない
3. **同じ時間で、実証済みのレバーを反復できる。**探索木を gen7 から採り直すのは約30時間で、そちらは14.2Mで+145〜196と測ってあるものの続きである

**この軸は閉じない。**「深さ8は約+25」という値札が付いたので、生成が安くなったとき(探索が速くなる、機械が空く)に戻ってくればよい。

### 4. 50%で自己改善ループに入る

固定深さで手書き評価に50%。**これを超えるまで、教師データの生成は手書き評価のまま**。負けている評価で `--eval-file` 生成に進むと、弱いラベルを蒸留するというgen1の構図に戻る。

超えたら `--lambda-score` を下げる検討もここから。教師超えを狙う段階の話で、今ではない。

## 規律

すでに確立したものの再掲。新しいものはない。

1. 判定は盤上のみ。残差指標はgen1・gen2・gen4の3点を説明できるもの(今は詰みを除いた探索木残差sd)だけを参考に使う
2. 対局の前に `training/drift.py` と `training/verify.py`。overnightのゲートをそのまま流用する
3. `info string eval nnue` の確認。50%近い結果はまず読み込み失敗を疑う

   > **8月27日、この規律の向きが片方増えた。**エンジンは `EvalFile` が未設定なら **exe と同じ場所の `eval.nnue` を自動で読む**ようになった(`option name EvalFile type string default eval.nnue`)。**「`EvalFile` を渡さなければ手書き」はもう成り立たない。**
   >
   > 手書き側を立てるときは `luna-match --option EvalFile=` を**明示的に**渡すこと。渡し忘れると両側がNNUEになり、**対手書きのつもりで自己対局を測る。**50%近い結果を疑うべき理由が一つ増えた形である(罠18)。
   >
   > 逆向きの事故 —— `EvalFile` の設定忘れで黙って手書きになる —— は、これで消えた。見つからない場合も `info string no eval.nnue beside the engine` と言う。
4. ホールドアウトはdatagen既定値で作らない。教師と同じ検閲を受け継ぐ。探索木ダンプを使う。**driftも同じで、探索木6000局面で回す**(8月17日に追加)
5. **世代間の比較は直前の世代との直接対決で測る。対手書き勝率は目標の指標であって、比較の道具ではない**(8月19日に追加)。gen4以降の帯域では差が3〜5倍に潰れ、121 Eloの改善が「p=0.90」として出た。400局のノイズ±3ポイントと重なると、100 Elo級が誤差に消える
6. **合格ラインを「既存の区間の外」で書かない**(8月19日に追加)。新しい側の不確かさを数えない検定になる。二標本で比べるか、直接対決で測る
7. **量子化の書き出しと drift の手続き**(8月19日に確定。それまで場当たりだった)

   - 補正元は**学習ファイルに探索木の行があればその行、無ければファイル全体**を65,536局面。**測定を見てから選ばない**。印(`RESULT_UNKNOWN`)は「木から来た」ではなく「対局が無い」を意味するので、印だけで判定しないこと
   - drift は `data/tree-gen2.labelled.sfen` 6000局面、閾値 **±20点**
   - 閾値20の根拠は Elo。gen1で34.6点の除去が +62 Elo と測られている(`docs/nnue-gen1.md`)ので、およそ1点1.8 Elo、20点で36 Elo。**この幅より小さい差を直接対決で主張するときは、両者の定数ずれを引き比べること**

   ±8 だったものを広げた。理由は、±8がこの手続きで達成できないからである —— gen5・gen6・gen7 が3回連続で落ち、そのたびに補正元を変えて通した。**そのうち1回(gen6)は tree-gen2 での drift を見てから補正元を選んでいて、測定集合に自由度1つを合わせる行為だった。**手続きを先に固定して閾値を実力に合わせるほうが正直である。

   既存のネットは再エクスポートしない(対局結果を出したファイルそのものなので、触ると記録が無効になる)。現行ファイルでの定数ずれは gen4 -7.9 / gen5 -3.7 / gen6-mix10 -2.5 / gen6-mix30 +1.3 / gen7 +16.2 で、全部この閾値の内側にある
