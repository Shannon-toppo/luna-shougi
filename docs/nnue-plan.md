## 順番

安いものから。判定は全部盤上で。

### 0. gen4を記録する

`docs/nnue-gen4.md` を書く。唯一針を動かした実験の記録が `data/overnight.log` 1本しかない。overnightスクリプトは設計としてdocsに書かないことにしていた(数字が成果物)ので意図した状態ではあるが、失敗3回をここまで使える形にしたのは記録の質で、成功だけ記録しない理由はない。30分。

### 1. score-weight を上に伸ばす

w ∈ {0.03, 0.1, 0.3} で同じパイロットを回す。39万局面スライス、30k step、総当たり各400局。仕組みはovernightのものがそのまま使える。半日。

0.03は端の勝者なので、探索はまだ終わっていない。どこかで決着帯の劣化が尾部の利得を食って頭打ちになるはずで(定数実験と同じ形)、知りたいのはその頭打ちの位置である。大きいwが正義なのではない。0.003が0より悪かったこと(総当たりで432.5対546)も覚えておく。**この項は小さく入れるとかえって悪くなることがある。**

`SCORE_HUBER_DELTA` を振るのはwのグリッドが決まってから。変数は1度に1つ。

勝者を1421万局面のフルレシピで学習してgen5。**合格ラインはgen4の9.8%を信頼区間の外で上回ること**。400局なら15%あたりが目安。

### 2. 教師の分布を探索木に寄せる

score-limitの一件で分かった本体は、ラベルの検閲のさらに下にある分布のずれである。**教師は対局に現れた局面、消費者は静止探索のstand-pat**(評価の84〜88%)。ラベルの帯は直したが、局面そのものの分布は手つかずのまま。

道具は揃っている。`EvalDump` で実物の局面を採り、`luna-datagen --label --depth 6` でラベルを付け、`data/gen3.bin` に混ぜる。**混合比は先に数字で決める**(10%と30%の2水準)。0.04%混合の再発(`docs/nnue-gen2.md` の罠7)はもうしない。

付け直しラベルと自己対局ラベルは一致しない(罠8)。測定は同じ付け方で統一する。

### 3. 深さ8はスライスの付け直しで試す

フル生成は77時間。払う前に、`data/gen3-slice.sfen` を `--label --depth 8` で付け直して39万局面のパイロットを作る。数時間で済む。盤上で効いたときだけ77時間を払う。

gen1の結論「深さ6以上」は「6で十分」を意味していない。ただしgen2で深さが主因でなかった以上、優先度は1と2の後。

### 4. 50%で自己改善ループに入る

固定深さで手書き評価に50%。**これを超えるまで、教師データの生成は手書き評価のまま**。負けている評価で `--eval-file` 生成に進むと、弱いラベルを蒸留するというgen1の構図に戻る。

超えたら `--lambda-score` を下げる検討もここから。教師超えを狙う段階の話で、今ではない。
