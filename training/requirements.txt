# Not the primary way in. Versions are managed by uv, from the pyproject.toml
# and uv.lock at the repository root:
#
#   uv sync
#   uv run python -m training.train ...
#
# That is what pins the CUDA build of torch, which PyPI does not carry. This
# file is kept for the two cases uv is not wanted for:
#
#   - CI, which only runs training/verify.py and so only needs numpy. There is
#     no reason for a 1.8GB torch wheel on every push.
#   - a plain pip environment, where the CUDA wheel has to be asked for by
#     hand or the CPU build turns up instead and training silently runs on the
#     wrong device:
#
#       pip install torch --index-url https://download.pytorch.org/whl/cu132
#       pip install -r training/requirements.txt
#
# cu132 matches the driver on the training machine; docs/nnue.md says how to
# check that it took.
numpy>=1.24
torch>=2.13.0
